## 2. 模块和唯一数据源

| 模块 | 输入与输出 | 禁止做的事 |
|---|---|---|
| LevelRepository | 校验关卡 → LevelDefinition | 根据图片识别位置来生成正式地图 |
| Planner | 地图、选格 → PlanAnalysis | 直接扣款、播放动画 |
| Economy | 当前账本、购买/退款/改建命令 → 新账本或错误 | 让 UI 自己算价格 |
| SupplyAllocator | 牧场分析、可用库存 → 分配表、缺口 | 预览时实际消耗库存 |
| NightResolver | 已提交快照 → 不可变 NightResult | 依赖物理碰撞或狼动画判断成败 |
| SessionController | 校验状态、事务、页面跳转 | 在场景销毁时丢弃账本 |
| PKService | 配置、随机种子、答题输入、有效比赛时间 → 结果 | 失败扣金币或叠加折扣 |
| SaveService | 版本化完整存档 → 恢复、备份、错误信息 | 只保存余额却丢掉购买批次 |
| Presentation | 渲染上述数据、发送用户命令 | 建第二套规则计算 |

跨场景只保留少量根服务，例如 SessionController、SaveService、ContentRegistry、AudioService；不要把每个类都设为全局自动加载。

### 2.1 数据对象最少字段

- `LevelDefinition`：schema_version、id、status、revision、width、height、terrain_rows、sheep[{id,x,y}]、wolf_entries、budget、initial_inventory、star_thresholds、pk_config、objective_key、tutorial_id、season、reference_solutions。
- `RuleConfig`：area_per_sheep=2、grass_per_sheep=2、water_per_sheep=1、fence_unit_price=1、grass_unit_price=2、water_bucket_price=4、water_units_per_bucket=4、discount_ratio=0.5。
- `PlanAnalysis`：规范排序的 selected_cells、components、每牧场羊 ID、A/P/W/F、boundary_edges、water_edges、fence_edges、自然资源、未圈羊、校验错误、plan_hash。
- `RunState`：run_id、level_id、level_revision、state_version、day_state、committed_cells、draft_cells、草稿撤销栈、ledger、purchase_batches、discount_active、pk_records、tutorial_progress、night_attempt_id、pending_night、last_result。
- `LedgerEntry`：transaction_id、command_id、type、amount、item_id、quantity、batch_id、unit_price、balance_after。金额为整数金币；amount 采用“支出正、退款负”的统一口径。
- `PurchaseBatch`：batch_id、item_id、purchase_unit（草份/水桶）、unit_price_paid、units_bought、resource_units_remaining、refunded_units、consumed_units。
- `Allocation`：牧场编号、自然草、自然水满足标志、购买草/水的预分配份数、批次预占明细、缺草/缺水。
- `NightResult`：attempt_id、输入快照哈希、success、risk_list、狼路径、每牧场达标详情、需消耗的批次明细、成本/星级、committed 标志。
- `ProgressSave`：schema_version、revision、解锁关卡、每关最高星级、原价最佳支出、折扣最佳支出、PK 最佳成绩、当前 RunState、设置。

JSON 里只保存基础数据；不保存 Node、Resource 路径引用、运行中的计时器或模型坐标。解析后必须转换整数类型并检查范围。相同输入的分析结果必须顺序稳定。

## 3. 页面、状态与输入

主页面：Home / LevelMap / Ranch / Town。覆盖层：Settings / Dialogue / BuildConfirm / Shop / PK / NightConfirm / Settlement。页面切换和玩法阶段分开管理，避免“商店场景加载 = 重新初始化关卡”。

### 3.1 正式状态流

```text
首次开始 → 第1关观察与引导
继续游戏 → 最近可恢复的白天状态（或待展示的已提交成功结算）
关卡地图 → 选择已解锁关卡 → 新建本关 RunState
白天观察 ⇄ 规划草稿 → 建造确认 → 白天观察
白天观察/规划 ⇄ 小镇 → 商店 ⇄ PK → 原商店
白天 → 夜晚确认 → 锁定快照 → 约10秒演出 → 结算
失败 → 修改（恢复入夜前）/ 重玩 / 地图
成功 → 下一关 / 重玩 / 地图；第8关改为完成首版并返回地图
```

| 操作 | 必须行为 |
|---|---|
| 首页“开始游戏”已有进度 | 二次确认；确认后新开游戏清除成绩和当前局，保留音量设置；取消完全不变 |
| 首页“继续” | 无可用存档禁用并说明；恢复当前关卡、草稿、账本、库存、折扣 |
| 地图点锁定关卡 | 显示前置条件，不进入；开发跳关仅测试版有 |
| 已解锁关卡重进 | 新局预算与物资恢复关卡初值，保留历史最佳成绩；离开未完成当前局先确认 |
| 规划去商店 | 草稿、撤销栈、已建方案保留；商店返回后继续规划 |
| 取消规划 | 草稿恢复已建格集，账本不变；清空仅本次规划撤销栈 |
| 草稿未提交时开始夜晚 | “建造并继续”“丢弃草稿并继续”“取消”；余额不足不得跳过建造错误 |
| 有缺口时入夜 | 显示风险清单；允许“仍然检验”；数据损坏或非法负余额不能启动 |
| 夜晚/结算中 | 禁用建造、购买、退货、改选；设置音量允许；重复点击不能重复提交 |
| 返回首页 | 白天先保存；有未提交草稿保留；PK 退出需明确放弃本次比赛，无奖励 |

夜晚期间默认不开放页面切换，只允许设置与跳过演出；关闭程序的恢复规则见第 9 节。

### 3.2 原生 UI 必备信息

- 首页：标题、开始、继续、设置；地图：8 个卡片、锁定原因、历史星级、进入按钮。
- 资源栏：金币、购买草库存、购买水库存；草水“+”打开对应商店商品；金币打开账单。无充值。
- 牧场卡：编号、羊数、面积当前/所需、自然草、自然水标记、分配草/水、缺口、安全状态。安全未知时显示“待检验”，不能假显示安全。
- 规划卡：A、P、W、F、改建差价；添加、擦除、撤销、重做、确认、取消。预览缺口明确标为“草稿预估”。
- 账单：围栏当前实付、草水采购净实付、退款记录、总支出、余额；自然资源不算购买库存。
- 小镇：固定小场景、商店建筑点击区、返回牧场；商店草、水两商品及购买/退货/挑战/关闭。
- 夜晚确认：已圈羊、容量、草、水、安全风险提示、预算，以及返回调整/开始检验。
- 结算：具体失败定位或星级；面积、周长、水岸、围栏费、补给费、节余、折扣状态；成功显示下一关，失败显示修改。
- 设置：音乐、音效/总音量、减弱动效、返回首页。设置立即生效并保存。

输入优先级：模态弹窗 > UI 按钮/卡片 > 规划选格 > 场景互动。UI 处理后不向世界穿透。普通对话除首段教学外可关闭，不长时间锁住操作。

规划仅支持左键/单指添加或擦除；一次按下到抬起算一个撤销步骤，拖过同格不重复操作。快速拖动需要格线遍历补齐经过格；跨出地图停止，重新进入不能莫名连接跨地图长线。失焦、弹窗打开、切换页面时结束笔划，避免持续选格。单次点击第一格必须立即反馈。

羊被点击只在观察态触发爱心、轻跳、咩声；规划时同一点击用于选地。视觉闲逛和动画不更改羊的逻辑出生格。

## 4. 网格、边界与建造

### 4.1 坐标与地形

策划坐标左上 (1,1)，x 向右，y 向下。数据文件保持 1 基坐标；程序内部可用 0 基，但只在导入/导出和 UI 边界转换一次。世界平面使用 XZ：格心 `(x-0.5,0,y-0.5)`，一格边长一引擎单位。不要把 y 行号当世界高度。

地形 `.` 普通陆地、`g` 产草陆地、`W` 水、`R` 山石、`B` 建筑。羊作为独立表记录，既可出生于普通地，也可出生于牧草地。原稿字符 S 必须导入为“g + 一只羊”，不能丢掉产草属性。

选地仅允许地图内的 `.` 和 `g`。水、山石、建筑、外侧狼行动带都禁选。装饰树、花、视觉雪皮不更改底层地形。

### 4.2 数学算法

1. 去重并校验格集合；BFS/DFS 用上、右、下、左四邻域拆分连通分量。对角接触不连通。
2. 每个分量的最小格按 `(y,x)` 排序，依次命名 A、B、C……；预览合并/拆分后允许重新编号，所有分配同步重算。持久标识可用规范格集合哈希，不能把临时 A 编号当永久主键。
3. 每个分量面积 A = 所选格数，共享边 E 每对只计一次，P = 4A - 2E。
4. 更直接的实施方法：遍历每格四边，邻格已选则跳过，否则加入边界集合。边界两端网格顶点排序后作为唯一 edge_id，禁止方向相反生成两段。
5. 边界外邻格是有效水格则为 water_edge；其余全为 fence_edge。W = water_edges 数量，F = fence_edges 数量 = P-W。
6. 孔洞边界照常计算；山石与建筑旁仍建栅栏；地图边缘仍建栅栏；水岸仍计 P。
7. 每牧场分析与全局总和分开输出。羊归属由其出生格是否在组件中决定，所有未圈羊单独列出。

围栏预览、已建模型、账单和狼阻挡全部读取同一份 fence_edges。边和顶点模型分别去重；模型转角/端柱不额外收费。门仅是美术变体，首版不引入可开门或免费边。

### 4.3 改建事务

`new_cost = new_F × 1`；`delta = new_cost - current_fence_paid`。预览显示 delta，正值扣、负值退；仅当新余额非负且仍在白天、快照版本没变时整体提交格集、边界、费用、账本和库存预分配。提交失败保持原状态完整不变。

空集是合法拆除方案，可确认全额退回当前围栏实付；它不能通关。允许建造面积/草水不足的方案，以便夜晚检验教学；不能把“存在风险”和“无法支付”混为一种禁止状态。

费用固定版本内不变。将来修改价格时，对正在进行的局保留开局价格快照，避免旧围栏退款被新单价放大。围栏不享受 PK 折扣。

## 5. 自然资源、容量与库存分配

对每个牧场独立计算：`area_need=2×羊数`，`grass_need=2×羊数`，`water_need=羊数`。

- 每个功能牧草格供草 1 份；自然草供给仅限本连通分量。
- 至少 1 条有效水岸就满足这个牧场所有羊当晚饮水，不把 W 当水份数。
- 空牧场允许存在，但其自然资源不能供给其他分量。
- 连通通道本身计面积；连接后全分量自然草水共享，围栏重新计算。不能简单“旧围栏相加再补通道”。
- 每次草稿/已建方案、库存或退款改变时，先完整清除旧预分配，再按 A、B、C 顺序补草缺口和水缺口。草、水独立分配；剩余库存可以分配给别的牧场。
- 分配只做预占，不减实际库存；顶栏同时可查看“购买库存 = 已预分配 + 未分配”。未圈羊不伪装成需求为零的成功状态。
- 自然草先用，购买草只补差；自然水满足则不分购买水。批次按购买先后预占，保证消费明细可重放。
- 只有夜晚成功提交才从购买批次扣除实际使用份数；失败不消耗。自然供给属于本关单夜计算，不重复采集到可售库存。
- 草篮/水槽只显示有对应购买物资预分配的牧场；自然资源也可播放吃喝动作，不要求买容器、不占面积。

## 6. 金币、购买、退款、防重复

| 项目 | 原价 | 胜利折扣 | 购买单位 |
|---|---|---|---|
| 围栏 | 1/段 | 不适用 | 随完整方案自动提交 |
| 草料 | 2/份 | 1/份 | 正整数份 |
| 水 | 4/桶 | 2/桶 | 正整数桶，每桶入库存 4 份 |

总支出 = 当前围栏实付 + 草水采购实付 - 草水退款。余额 = 开局预算 - 总支出。金币和资源全用整数，不使用浮点近似金额。不能靠完成引导、失败、重复打开结算领钱。

购买命令在提交时重新检查商品、数量、价格、白天状态、余额及版本；数量 UI 的禁用不能代替服务校验。按钮在处理期间禁用，服务按 command_id 去重，即使回调重复也只写一笔账。

### 6.1 退款开发默认值

原稿只规定按购买批次实付退回未消耗物资，未规定多批次顺序和水的拆零退款。采用：

1. 草按份退，水按完整未消耗桶退；UI 显示“可退 N 份/桶”，不让玩家输入含糊的水份退款。
2. 按最新购买批次优先退款；提供退款明细预览。例如原价草 2 份 + 折扣草 2 份，退 3 份退款为 1+1+2=4。
3. 自动预分配不是消耗，退款前释放后重算，可能使牧场缺草缺水，明确展示。
4. 当前设计每关只有一夜、成功即结算，白天没有部分消费水桶；若恢复的数据存在部分已消费桶，剩余散份不得按整桶退款。将来多夜扩展再定义散份政策。
5. 未提交的失败夜晚恢复同一批次余额，原价购入不能追溯折扣价，折扣购入不能按原价退。

账本、批次、余额、库存、已建方案必须作为同一状态写入；不允许动画播完才更新余额。事务遵循“读版本 → 全部校验 → 计算候选新状态 → 持久化 → 切换内存快照 → 发事件”。存档失败不显示“已安全保存”，保留可重试事务 ID，不再次收款。

## 7. 夜晚、狼与结算

### 7.1 狼行动图

地图外围保留一圈可通行但不可选地的逻辑陆地，坐标范围 `x=0..width+1, y=0..height+1`。地图内按真实地形构图；水、山石、建筑不可进入。外圈与内部之间按共同格边检查 fence_edges，不能绕过地图边缘围栏。

狼入口必须落在外圈有效节点，不能在玩家选地内部。开发默认一只狼、一个关卡指定入口；模块接受入口列表，多入口时逐一检查并汇总风险。

从入口做四向 BFS。经过边有已建栅栏则不可走，水格不可走，不能斜穿角。可到达羊时选最短距离，距离相同按固定羊 ID，再按固定入口 ID 决定；邻居顺序固定上、右、下、左，使路径重放一致。

没有可达羊时，从可达外部节点中找围栏相邻位置，生成短巡逻路径；找不到就原地嗅闻离开。视觉路径只能使用合法图路径，不能为了演出把狼直线插值穿水穿栏。

### 7.2 确定性判定

NightResolver 只读取已提交快照，输出全部问题：未圈羊、狼可达羊、每牧场容量不足、缺草、缺水、余额非法。通关要求全部任务羊归属有效、各牧场面积够、草水够、任意入口的狼都到不了羊、余额非负。

不允许因为自动围栏闭合就跳过羊归属和需求，也不允许只检查全局面积/资源。多余牧场不抵消其他牧场不足。

失败显示顺序：安全风险（含未圈羊）→ 拥挤 → 缺草 → 缺水；非法账本作为内部错误阻止入夜并提供恢复选项。每条包含 sheep_id 或牧场组件定位、当前值、需求值、差额和对应文字键。

### 7.3 夜晚事务时序

1. 处理草稿三选项，确认风险后生成 attempt_id 和白天快照，保存“夜晚待完成”。
2. 纯规则生成 NightResult；进入锁定夜晚态。
3. 约 10 秒演出按结果播放：昼夜渐变、灯亮、狼路径、风险定位；成功则羊吃喝睡觉。音频或动画缺失也必须按超时回退继续。
4. 演出结束/跳过调用一次 finalize(attempt_id)。成功时一次性提交消费、星级、最佳成绩、解锁及结果记录；失败不改白天经济数据。
5. 成功存档完成才展示可离开的成功结算。重复 finalize 返回同一结果，不重复消费/解锁。
6. 夜晚未提交时退出重开：恢复入夜前白天，不扣物资；成功已提交但结算未展示：展示保存的成功结果，不再扣物资。第 9 节的存档必须让这两个分支可区分。

“修改”只在失败结果中恢复入夜前全部白天状态，包括草稿处理后的方案、批次、余额、折扣。已建围栏不重新收款。“重玩”创建新 run_id，恢复关卡初始预算和库存。

### 7.4 星级和纪录

失败 0 星；成功按总支出由低到高检查：≤ 三星阈值为 3 星，否则 ≤ 二星阈值为 2 星，否则为 1 星。阈值必须满足 `三星 ≤ 二星 ≤ 预算`。

默认纪录分组以“本局是否解锁折扣”为键，并同时保存是否实际折扣采购、折扣采购净额；展示该分组口径。PK 胜利但未买东西仍进入折扣组，以免分类含糊。团队将来可调整分组展示，原始交易记录保留。

PK 用时不参与牧场星级。最高星级取历史最大；同组最佳支出取成功记录最小；未通关记录不能覆盖最佳成绩。

## 8. PK 完整执行规则

原稿已定：商人在左、玩家在右、四选一、答对 5 题竞速、错答不涨进度、退出不领奖、获胜后本关草水五折不叠加；第 1～5 关正式入口关闭，第 6～8 关开启，所有关卡均可原价通过。

| 配置 | 第 6 关 | 第 7 关 | 第 8 关 |
|---|---|---|---|
| 商人完成 5 题用时 | 30 秒 | 25 秒 | 22 秒 |
| 题型 | 两数加减，数值/结果在 0～20 | 两位数加减，结果非负 | 两位数加减混合，含少量进退位 |

为避免歧义，开发默认：第 7～8 关操作数均 10～99，减法交换操作数保证非负，允许加法结果大于 99；第 8 关“混合”先指同场混合加减题，不擅自加入三操作数。进退位比例分别暂设 20% 与 30%，数据可调，不表示已试玩标定。

其余开发默认值：

- 商人每 T/5 秒推进一题，时间到 T 则完成；不用真正生成一个 AI 对手。
- 正确答案使玩家进度 +1 并生成下一题；错答保持题目、禁用刚选错项，短反馈后可继续。一次题号只接受一次正确提交，连续点击不能跳两题。
- 使用可测试的有效比赛时钟，后台/失焦暂停双方，并显示继续遮罩；VS 入场与规则页不计时。不能只暂停商人、不暂停玩家。
- 玩家第五题提交时间严格小于 T 才胜；恰好等于 T 为平局、无奖励。该口径可配置并在规则页说明。
- 原稿没有错答罚时，默认不罚时。允许免费重试，无次数上限；已获折扣再赢只记录成绩。
- 四答案互不重复、恰好一个正确；干扰项必须合法且非负。候选集合不够时补选，避免无限随机循环。记录种子与题目便于复现，不保存答案顺序为固定位置。
- 退出返回原商店、保留草稿和采购记录，不领奖；再次挑战重新计时、生成新场次。
- 关闭应用不恢复半场比赛；恢复白天并保持此前已提交的折扣。获胜事务和 PK 纪录一起保存，奖励唯一键为 run_id+折扣权益类型。

UI 明确显示 5 格双方进度、算式、四选项、剩余时间或比赛进度、退出。结果只有胜/负/平和折扣提示，不能增加金币或奖杯系统。

## 9. 存档与异常恢复

原稿要求“继续恢复最近白天”，只在挑战/成功保存不足以满足。因此补充保存时机：建造、购买、退款、挑战结束、引导推进、返回首页、设置改变；草稿在一次笔划结束后合并保存。不能只依赖关闭网页事件。

保存到 `user://`，使用版本化完整快照。采用两个存档槽位交替写入，每份包含递增 revision、payload 与校验值；写完读回验证，加载时选择最高版本有效快照，另一个作为回退。不要在同一文件上先清空再写。Web 的持久化行为仍必须实机刷新验证，文件写入成功不等于每个浏览器都保证永久保存。

加载校验 schema、类型、关卡版本、坐标、购买批次和账本等式；可以重新计算的缓存一律重算。旧 schema 有明确迁移函数与测试；版本更新导致地图变化时不强行套旧选格，保留历史成绩，提示重开该关。未知更新版存档不能静默覆盖。

存档损坏时先尝试另一份备份；均失败则提示“无法读取进度”，允许备份/导出原始数据后重开，不默认清空。浏览器不允许持久化时明确提示本次只能临时游玩；可补充导出/导入存档入口，导入内容必须校验而非执行代码。

浏览器本地存档按网站来源隔离，本地测试保持相同主机名和端口；换网址、清除站点数据或隐私环境可能无法续玩。正式试玩前检查刷新、关闭重开、后台恢复、存储失败，不承诺云同步。
