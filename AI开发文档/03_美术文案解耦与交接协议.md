# 03｜美术、文案与程序的独立开发和合并协议

本文件同时交给程序、美术和文案成员。程序成员负责把接口做成可运行实物；不能只写“以后可替换”而让美术合入时重新制作全部场景。

## 1. 三方工作边界

| 成员/阶段 | 主要编辑区域 | 交付内容 | 不应修改 |
|---|---|---|---|
| 程序 | scripts、scenes 的逻辑壳、data、tests | 完整占位游戏、槽位、清单、验证器 | 未经说明的正式文案和模型源文件 |
| 美术 | assets/final、content/art、主题资源 | 模型、透明图、连续动画、音频、皮肤与映射 | 价格、关卡判定、存档、输入命中算法 |
| 文案 | content/text、对话与引导内容表 | 文案键值、变量、对话顺序建议 | 硬编码数值、脚本逻辑、素材路径 |

任何一方的正式内容缺席，程序仍必须可以玩。合并由程序成员执行 manifest 映射与校验，无需在每个玩法脚本里查找替换路径。给美术/文案的底包使用同一个内容协议版本，例如 `content_schema_version=1`。

## 2. 场景搭建规范

### 2.1 基准画面

原稿第 10 节采用奶油白、浅草绿、鼠尾草绿、淡木色；低模多边形折面、哑光平涂、柔和影子。夜晚偏深蓝绿、暖窗；冬季只换皮，不改水源和产草规则。

程序阶段用带颜色的简单网格块、简化羊体、木色围栏体现尺寸和轮廓，避免用完全不同的 2D 玩法布局临时凑数。正式模型直接落在同一 3D 格子场景中。

建议场景树：

```text
RanchRoot
  WorldRoot
    TerrainRoot          # 可选地、水、障碍的视图
    GrassMarkerRoot      # 功能牧草叶片标记
    BoundaryRoot         # 已建围栏、顶点柱
    DraftOverlayRoot     # 草稿边界/选中/禁选覆盖
    SheepRoot            # 羊逻辑锚点 + VisualRoot
    SupplyRoot           # 草篮、水槽表现
    WolfRoot             # 按规则路径播放的视图
    DecorationRoot       # 无规则效应
    LightRig             # 昼夜参数
    CameraRig/Camera3D
  GridPicker             # 统一屏幕到逻辑格转换
  CanvasLayer
    SafeArea/HUD
    ModalHost
    ToastHost
```

正交相机默认斜俯角约 35°、水平偏转约 45°，这是可调视觉默认值，不参与规则。通过地图世界包围盒和 UI 实际可用矩形自动取景，保留狼外圈；原理参考 [Godot Camera3D](https://docs.godotengine.org/en/4.5/classes/class_camera3d.html)。镜头不旋转，鼠标映射必须走当前 Camera3D 射线与地平面求交，再变换到局部格坐标。缩放、窗口比例或 UI 卡片收起后仍准确。

羊根节点固定逻辑出生格，VisualRoot 可小幅移动。闲逛半径不越出所属安全表现区域，不把视觉运动写回数据。狼根节点沿确定路径移动；相邻格之间分段运动，不能平滑曲线切入禁区。树木与装饰不能成为游戏阻挡，除非关卡数据明确指定。

### 2.2 UI 布局合同

基准 1280×720；顶部资源栏，侧边任务/牧场卡，底部规划操作，地图中央最大。使用 Container、Anchor 和 Theme，不靠固定绝对像素拼所有节点。小屏优先折叠侧卡，面积/费用/确认仍可达；竖屏显示横屏提示，不出现无法关闭的弹窗。

- 纸卡背景、木色边框用可九宫格拉伸资源；正文、金额、编号、禁用态全部原生控件渲染。
- 策划参考图里的 40/120 金币、围栏商品、木材、奖杯和资源奖励全部不能直接采用。
- 按钮状态至少 normal/hover/pressed/disabled/focus。触控目标至少 44×44 逻辑像素，图标小也要有足够透明点击区。
- 选中、禁选、缺资源同时有线框/图标/文字，不能仅红绿区别。
- 弹窗有遮罩、焦点和关闭策略；Esc 关闭最上层可取消弹窗，不能直接退出未保存关卡。
- 正文中文字体必须随包可用并记录许可；符号、数字、负号不缺字。不要依赖系统恰好安装某种字体。
- 两行对话过长则按段分页，其他说明可滚动；重要按钮和数值不靠省略号隐藏含义。

## 3. 资产清单与资源 ID

所有路径通过 `ArtManifest` 获取；例如 `sheep.default` 映射到一个 Godot 包装场景，不让逻辑层直接加载任意 GLB。包装场景负责模型缩放、朝向、动画名称适配与选择高亮锚点。

以下尺寸是程序占位/接口初值，可由美术调包装层；不能通过改世界格长来修正模型尺寸。

| 稳定 ID/类别 | 必需内容 | 合同 |
|---|---|---|
| terrain.land / terrain.grass | 普通地、产草地 | 平面占 1×1，顶面 Y=0；草格另有明显叶片标志 |
| terrain.water / terrain.rock / terrain.building | 水、山石、建筑禁选 | 阻挡来自数据；视觉不能扩大禁选范围 |
| fence.segment / fence.post | 栏段、柱 | 栏段长 1，默认沿本地 +X，轴心在段中心底部；柱以顶点为底部中心 |
| fence.corner / fence.gate_visual | 可选角/门外观 | 不另收费；门首版始终阻挡，不可开启 |
| sheep.default | 羊模型、状态动画 | 脚底轴心，建议宽深≤0.65格，前向约定 -Z |
| wolf.default | 狼模型、状态动画 | 脚底轴心、-Z前向；不可用动画根位移改变规则路径 |
| actor.player / actor.merchant | 牧场主、商人 | 草帽背带裤/棕发绿围裙保持身份一致 |
| portrait.player / portrait.merchant | 2D头像表情 | 与场景人物同身份；统一透明边距 |
| supply.grass_basket / supply.water_trough | 草篮、水槽 | 仅表现、不占面积、不收费、不改变通行图 |
| town.shop | 商店 | 建筑外观与可点击逻辑壳分开；屋顶/窗灯可切换 |
| town.counter/sign/awning/flowerbox/lamp/bench/path | 小镇组件 | 可独立拼装；缺失不影响商店功能 |
| decoration.grass/flower/tree/butterfly | 装饰 | 不产草、不阻路、不截获规划输入 |
| fx.heart / fx.purchase / fx.selection | 互动、采购、选地反馈 | 可为空或用简单占位；有时长上限 |
| ui.theme / ui.icons.* | 纸卡、按钮、资源图标、星级 | 不包含烘焙数值和正文 |
| audio.music.day/night/town/pk | 背景音 | 通过音频服务切换、可静音 |
| audio.sfx.sheep/build/buy/refund/correct/wrong/result/click | 一次音效 | 重复触发限流；缺文件静默回退 |
| lighting.day/night / season.spring/summer/autumn/winter | 光照及换肤 | 不更改功能地形和规则 |

文件建议使用小写英文蛇形命名，不含空格，如 `sheep_default.glb`。单独保留美术源文件，在程序运行包里只装导入后的必要资源。全部资源记录来源、作者、使用许可、是否允许随游戏分发。

### 3.1 建议的 manifest 内容示例

```json
{
  "schema_version": 1,
  "content_version": "placeholder-1",
  "assets": {
    "sheep.default": {
      "scene": "res://content/art/sheep_wrapper.tscn",
      "fallback": "res://assets/placeholder/sheep.tscn"
    },
    "fence.segment": {
      "scene": "res://content/art/fence_wrapper.tscn",
      "fallback": "res://assets/placeholder/fence_segment.tscn"
    }
  }
}
```

此处只演示结构，程序需生成上表完整清单。加载时检查资源存在、类型、预期节点/锚点；缺失用 fallback，记录可读诊断。正式交付前由验证器报告哪些仍为占位，不能悄悄把缺资源当“全部正式完成”。

## 4. 动画与音效接口

逻辑只发语义事件，动画系统订阅播放；播放结束可以通知流程，但流程必须有超时和跳过回退。

| 语义动作/事件 | 表现建议 | 不允许影响 |
|---|---|---|
| sheep.idle / walk / eat / drink / scared / sleep / pet | 多朝向，吃喝、受惊、睡觉、摸头轻跳 | 羊逻辑坐标、资源需求 |
| merchant.welcome / handover / calculate / think / celebrate | 商人欢迎、递货、算账与结果 | 购买是否成功、折扣是否生效 |
| player.idle / pet / think / celebrate | 牧场主状态 | 解锁、羊归属 |
| wolf.appear / walk / sniff / confused / leave | 非暴力巡视，无法到达就离开 | 狼的合法路径与安全结果 |
| plan.preview_changed(analysis) | 选格与边界高亮 | 余额、库存 |
| build.committed(edge_ids, delta) | 围栏逐段出现、音效 | 收费时机和段数 |
| supply.changed(allocation) | 草篮/水槽显示、数字跳动 | 分配计算 |
| night.started(result) / night.finished(attempt_id) | 昼夜转换、风险镜头、吃喝睡觉 | 判定与重复结算保护 |
| pk.answer_result(question_id, correct) | 选项正误反馈 | 题目进度幂等校验 |
| environment.clicked(id) | 草轻摇、蝶飞起 | 草产出、金币 |

美术动画名称可以任意，但包装层必须提供语义映射。缺 `drink` 可暂用 `idle` 加水图标，缺 `sleep` 可静态闭眼占位；缺资源不能等一个永不发出的 animation_finished。

减弱动效模式：关闭晃屏、短促缩放、长镜头移动和密集粒子，缩短围栏出现与昼夜过程；仍显示数字、选中边框、风险定位、胜负。无声/减弱动效下完整可玩。

## 5. 文案数据与变量

所有面向玩家的文字走 `TextCatalog.format(key, params)`，包括按钮、错误、引导、商品名、单位、设置、关卡名、动态风险。开发日志可以直接写技术文字。禁止在正式文本里写死金币和羊数。

建议 UTF-8 JSON 作为主表，CSV 可作为文案导入格式。程序统一解析变量与转义；文案不写脚本、不拼条件表达式。

```json
{
  "schema_version": 1,
  "locale": "zh_CN",
  "strings": {
    "home.start": "开始游戏",
    "home.continue": "继续游戏",
    "planner.fence_count": "需建栅栏 {count} 段",
    "planner.delta_charge": "本次需付 {amount} 金币",
    "planner.delta_refund": "本次退回 {amount} 金币",
    "ranch.area": "面积 {current}/{required} 格",
    "risk.grass_shortage": "牧场 {ranch} 还差 {amount} 份草",
    "risk.unenclosed": "小羊 {sheep} 还没有被圈进牧场",
    "shop.water_unit": "{price} 金币/桶，每桶 {units} 份",
    "level.01.request": "今晚有点凉，给我们围一个能睡觉的小院吧。",
    "level.02.request": "池塘能供水，也能帮我们省一段栅栏。"
  }
}
```

前两关委托来自策划原稿，其他占位文字明确标 `draft`。每个键另附上下文说明、参数类型、建议长度、是否允许换行、出现位置截图编号，防止文案改错变量含义。

最少键域：`home.*`、`map.*`、`level.01..08.*`、`tutorial.*`、`planner.*`、`ranch.*`、`shop.*`、`refund.*`、`pk.*`、`night.*`、`risk.*`、`result.*`、`settings.*`、`save.*`、`common.*`、`unit.*`。正式值允许改，键名与参数签名需要接口版本管理。

文本校验器要求：重复键失败；缺必需键列清单；参数增删/拼写不符失败；数字占位符不能静默变空；非法控制字符报错。运行时非关键缺失可回退到内置测试文案，同时记录错误；开发版可显示 `[missing:key]`，正式包必须在出包前清零缺键。

对话用 `dialogue_id + 节点列表 + speaker_id + text_key + 下一节点/关闭`，教学步骤的完成条件由程序定义，文案不能把“买一桶水”的条件改成纯粹“点继续”。剧情改动涉及流程时必须另提变更。

## 6. 美术资源合入步骤

1. 程序交出 M1 可运行底包、完整槽位表、样例包装场景、单位/轴心/前向说明、状态演示入口。
2. 美术先交一只羊、一段围栏、一种地块、一个按钮皮肤试装；通过后再批量制作。
3. 模型从 Blender 导出 GLB；脚底轴心、应用缩放、检查材质及贴图。原参考 PNG 是设定图，不是可直接使用的模型或连续动画。
4. 程序在包装场景中挂 GLB，映射语义动画，调整视觉尺度；不编辑导入生成的只读模型资源来塞玩法脚本。
5. 运行资源验证器，再测试点击、规划、围栏、水岸、狼、不同窗口及夜间可读性。
6. 对比替换前后同一参考解的 A/P/W/F、金币、库存、NightResult，必须完全一致。
7. 正式合并，登记内容版本、许可和仍缺素材；没有通过则保留旧占位回退。

## 7. 文案合入步骤

1. 程序导出带上下文的完整键表，文案在值列修改，不删除键与变量。
2. 先试装首页、商店、失败提示、两段对话四类文字，检查短句/长句和变量。
3. 全量校验文本键、变量和编码，再扫描玩家可见硬编码字符串。
4. 在1280×720与小屏检查折行、对话两行分页、按钮、金币和缺口不截断。
5. 同一关卡重新通关，文案更换不得改变价格、地图、解锁和存档。
6. 记录文本内容版本，可独立回退到旧文本表。

## 8. 合并完成的最低证明

- 关掉正式美术目录映射仍可用占位通关。
- 整套换皮不修改 domain/application 规则文件。
- 羊动作缺失、声音缺失时流程不会卡住。
- 换成两倍长度文本，关键 UI 可操作，错误原因可读。
- 所有接口资源与文本校验通过，同一固定输入的规则测试前后相同。
- 交接人收到的不是“找程序员改路径”的建议，而是一张稳定 ID 到文件/文本值的明确表和实际替换样例。
