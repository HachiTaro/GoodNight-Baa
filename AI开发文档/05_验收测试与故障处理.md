# 05｜验收测试、通过门槛与故障处理

本文用于验收未来生成的游戏。表中的期望值是测试标准，不是已测结果。执行时为每项增加“通过/失败/待测、版本、证据”列；缺少设备或未运行必须写待测。

## 1. 什么才算完成

M1：前两关流程、数学、经济、狼、存档、UI和Web相关测试全部通过。M2：再通过多牧场、PK、八关与替换测试。阻断问题包括：无法启动/通关、错误扣费、资源复制、负余额、漏圈仍通关、读档丢账、重复结算、UI无法操作、Web不能运行。

轻微美术缺失可以保留占位并列出，但不能以“等美术”为由留下打不开的商店、不能关闭的弹窗或无反馈的按钮。

## 2. 零基础人工通关脚本

### A. 第一关标准成功

1. 首页开始；如有旧档用独立测试存档或先备份，避免覆盖真实进度。
2. 点羊看每羊面积2、草2、水1；进入规划。
3. 添加 (3,2)(4,2)(3,3)(4,3)。规划卡应为 A4、P8、水岸0、栅栏8。
4. 确认建造，预算16变余额8；自然草4满足，缺水2。
5. 去小镇点商店，水数量1桶，总价4，购买后余额4、购买水库存4份。
6. 回牧场，购买水预分配2、未分配2；开始夜晚。
7. 狼不能进入；羊睡下，3星、总支出12、节余4，成功后水剩2。
8. 关闭结果后重开/刷新，纪录不变、不再次减水；第二关解锁。

### B. 第一关失败修改

1. 重玩第一关，按A的四格建造，不买水。
2. 开始夜晚，风险明确“牧场A缺水2”；允许继续检验。
3. 失败无星，点“修改”，余额仍8、围栏仍8、草水购买库存仍0。
4. 买一桶水再入夜即可成功；不是重开预算，也不重新扣围栏8。

### C. 第二关两解对照

每次从重玩开始。竖向选x3～4/y2～5，围栏12，买草4份花8、买水1桶花4，总24、余额0、1星。横向选x2～5/y3～4，围栏11、自然草8、临水，不买物资，总11、余额13、3星。

### D. 连接与折扣反转

按04的第5/7关选格。先分别开新局验证分开31、连通27。第7关再新开局，赢PK后分开购买草4份和水1桶，总25；连通不买物资仍27。不能在已经原价买过物资的局中直接期待总价自动降为25。

## 9. Web、性能与发布前检查

Web 基线：GDScript + Compatibility + 单线程。目标浏览器需要 WebAssembly/WebGL2；实际设备是否支持以真机测试为准。浏览器音频首次交互、持久化与后台行为可参考 [Godot Web 导出说明](https://docs.godotengine.org/en/4.5/tutorials/export/exporting_for_web.html)，不能凭编辑器表现推断网页表现。

1. 从干净导出目录重新导出，整组文件同版本；通过 HTTP 打开，不用 file://。
2. 在目标教室电脑真实浏览器完成第一关、第二关横向解、一次PK、一次刷新恢复；记录系统、CPU/GPU或设备型号、浏览器完整版本、分辨率。
3. 浏览器控制台和Godot输出无阻断错误；检查资源404、wasm/MIME问题、字体缺失、音频未解锁。
4. 性能开发目标（待设备实测批准）：目标设备持续交互至少30FPS，争取60FPS；选格到可见反馈不超过100毫秒；单次拖动不出现明显卡顿。报告必须写测量条件和方法。
5. 初次加载时间记录包体、网络条件、冷/热缓存，不在没有实测时承诺秒开。调优先减少装饰、透明叠层、实时阴影、重复模型和过大纹理，不改变数学规则。
6. 第8关视图压力通过后，可额外做23羊性能场景；它不是新正式关卡，也不能替代八关流程测试。
7. 重复进出牧场/商店20次，无节点/音频重复叠加、事件重复订阅、显著持续内存增长；若有增长记录并修复。
8. 正式包无调试加钱、跳关、答案、参考解自动填充；必要日志不包含用户敏感信息。
9. 输出仍为Web试玩包，不宣称已经完成微信小游戏适配。若尚未正式美术/文案合入，写明占位程序版。

## 10. 常见错误怎么处理

| 现象 | 先查什么 | 交给AI的修复方向 |
|---|---|---|
| 工程打不开/脚本解析报错 | Godot版本、第一条错误 | 用固定4.5.2核对API和类型，不删除整套系统 |
| F6能玩，F5空白 | 主场景、Boot路由 | 设置全项目入口并跑完整启动链 |
| 选格偏一行或点不到 | 1基/0基、XZ映射、相机转换 | 做四角坐标往返测试，不能移动素材硬凑 |
| 2×2周长不是8 | 共享边、边去重 | 修唯一Planner算法，UI不要另补数字 |
| 水岸把面积变大/把周长变小 | 水选入、W处理 | A只陆地，P照算，F=P-W |
| 画了围栏羊仍被狼穿过 | 图边ID与模型边数据不一致 | 统一fence_edges，禁用物理碰撞裁决 |
| 退款越退越有钱 | 批次实付、单位、重复提交 | 退款按批次、整桶水、幂等事务 |
| 失败后物资少了 | 预分配和消耗混淆 | 仅成功finalize消费，失败恢复快照 |
| 进商店回来地形/钱重置 | 场景初始化覆盖会话 | SessionController持有本局状态 |
| PK错答也推进/连点过两题 | 当前题ID、提交锁 | 每题只接受一次正确提交 |
| 中文方框 | 字体资源/导出包含范围 | 包含有许可的中文字体，测试实际导出 |
| Web空白或打不开 | file://、导出整包、WebGL2、控制台 | 用本地HTTP，同版本模板、Compatibility |
| Web刷新不保存 | 来源变化、存储权限、过晚保存 | 固定来源、事务后保存、真实持久化验证 |
| 动画播完不结算 | 只监听动画完成信号 | 加确定结果、超时、跳过与幂等finalize |
